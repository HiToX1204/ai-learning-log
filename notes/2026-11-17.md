## 二、细知识点

### 1. `Value` 类存了什么

```python
self.data = data                 # 值
self.grad = 0.0                  # 梯度（初始 0）
self._prev = set(_children)      # 父节点集合（我是从谁算出来的）
self._op = _op                   # 运算符，仅用于调试
self._backward = lambda: None    # 反向传播函数，默认空操作
```

**`_prev` 的唯一来源**：`__add__` / `__mul__` 里创建 `out` 时把 `(self, other)` 传进去。叶子节点传的是空元组。

### 2. 闭包 + 函数对象

```python
def __mul__(self, other):
    out = Value(...)
    def _backward():        # 嵌套函数，捕获 self/other/out
        ...
    out._backward = _backward   # 存"函数本人"，不是调用结果
```

- `_backward`（无括号）= 函数对象，可以赋值
- `_backward()`（有括号）= 调用，返回 `None`
- **所以"没有返回值"和"能赋值"不冲突**

### 3. 运算符重载

| 写法 | 调用 | 方法 |
|---|---|---|
| `a + b` | `a.__add__(b)` | `__add__` |
| `a * b` | `a.__mul__(b)` | `__mul__` |
| `a == b` | `a.__eq__(b)` | `__eq__` |
| `a[0]` | `a.__getitem__(0)` | `__getitem__` |
| 直接敲 `a` | `a.__repr__()` | `__repr__` |
| `1 + a` | `a.__radd__(1)` | `__radd__` |

- 先调左操作数的方法，返回 `NotImplemented` 再调右操作数的 `__radd__`
- **`_op` 不参与计算**：行为由"创建时挂上的那个函数"决定，不是运行时判断字符串
- 加新运算 = 写新的 `__sub__` 等方法，不需要改已有代码

### 4. `_backward` 的两条规则

```python
# 加法：原样分（局部导数为 1）
self.grad  += out.grad
other.grad += out.grad

# 乘法：乘对方的值（∂(a·b)/∂a = b）
self.grad  += other.data * out.grad
other.grad += self.data  * out.grad
```

**通用形式：`我的梯度 += 局部导数 × out.grad`**

- `out.grad` = 上游传下来的总量（**不能写死 1.0**）
- 局部导数 = 我对上家的直接影响系数

### 5. 为什么必须用 `+=`

多路径时，同一变量从多条路径收到梯度，**要相加**（全导数 = 各路径偏导之和）。

```
dL/dx = (∂L/∂e)(∂e/∂x) + (∂L/∂g)(∂g/∂x)
```

用 `=` 会覆盖前一次的值。以 `e=x*y`、`g=x*z`、`L=e+g` 为例：`+=` 得 `3+5=8`（正确），`=` 得 `5`（少一半）。

**同一机制解释了 PyTorch 为什么要 `optimizer.zero_grad()`**——不清零，梯度会跨轮累加。

### 6. 拓扑排序（后序 + 翻转）

```python
def backward(self):
    topo, visited = [], set()
    def build(v):
        if v not in visited:
            visited.add(v)
            for child in v._prev:
                build(child)
            topo.append(v)      # ← 必须在递归之后
    build(self)
    self.grad = 1.0
    for node in reversed(topo):
        node._backward()
```

- **`append` 在递归之后**（后序）→ `topo` 是"输入在前"
- **`reversed`** → 变成"输出在前"
- **两者只要翻一次**：`append` 在前 + `reversed` = 翻两次 = 回到错的顺序

### 7. 为什么必须"输出在前"

一个节点必须**等它所有下游的梯度都到齐**，才能往上传。

`x,y → e → f → d`（且 `e` 也被 `d` 直接用）：

- 正确顺序 `d, f, e, …`：`f` 先给 `e` 转账，`e` 结算时 `grad=2`
- 错误顺序 `x, y, e, z, f, d`：`e` 在 `f`、`d` 之前结算，`e.grad=0`，于是 `x.grad = 3×0 = 0`

**不报错，但结果全错。**

### 8. `grad` 的语义

`a.grad = -3` 的意思是：**`a` 增加 1，最终输出减少 3。** 它就是偏导数，可用 `num_diff` 独立验证。

## 四、今日最大收获：两种把抽象机制讲清楚的图

> 这一节是本人认定"最有价值"的部分，因为它把两个看不见的机制变成了能看见的东西。

### 收获 A：用"分账"理解为什么必须"后序 + 翻转"

**图**：

```
x ──┐
    ├──▶ e ──┬──────────▶ d
y ──┘        │            ▲
             │            │
             └──▶ f ──────┘
                  ▲
z ────────────────┘
```

关键：`e` 有**两条下游路径**（`e→d` 直连，`e→f→d` 绕一层）。

**分账过程**（把 `d` 看作"总账单 1 块"）：

1. `d` 结账：给 `e` 1 块、给 `f` 1 块 → `e.grad=1`、`f.grad=1`
2. `f` 结账（`f=e+z`，原样转）：给 `e` 1 块、给 `z` 1 块 → **`e.grad=2`** ★
3. `e` 结账（`e=x*y`）：给 `x` 转 `y×2`、给 `y` 转 `x×2`

**★ 是关键**：`e` 必须等到 `f` 给它转过账，才能结算。

**前序为什么错**（时间轴）：

```
时间 →
d ──→ e ──→ x ──→ y ──→ f ──→ z
      ↑                  │
    e 结算               └─ f 这时才给 e 转 1 块
    （手上只有 1 块）        （e 早已结算，这 1 块作废）
```

`e` 结算时手上只有 1 块 → `x.grad = y×1`，本该是 `y×2`。

**后序 + 翻转为什么对**：

```
后序：  x → y → e → z → f → d
翻转：  d → f → e → y → x → z
            ↑  ↑
            │  e 结算
            f 先给 e 转账
```

**原理**：后序的规则是"一个节点要等所有孩子都排完，才轮到自己入列"（依赖全部到位才登记）。
所以任何边 `A→B`，`A` 必在 `B` 之后；翻转后 `B` 在 `A` 前 —— 正好"下游先结算"。

> 一句话：**后序 = 等所有账收完再登记；翻转 = 从总账开始倒着算。**

### 收获 B：用具体数值把 `backward()` + `_backward()` 走一遍

**造图**（`x=2, y=3, z=1`）：

```python
x = Value(2.0); y = Value(3.0); z = Value(1.0)
e = x * y     # 6.0
f = e + z     # 7.0
d = e + f     # 13.0
```

| 节点 | data | _prev | _backward 里捕获 |
|---|---|---|---|
| x,y,z | 2,3,1 | set() | `lambda: None`（空操作） |
| e | 6.0 | {x,y} | 乘法版，捕获 (x,y,e) |
| f | 7.0 | {e,z} | 加法版，捕获 (e,z,f) |
| d | 13.0 | {e,f} | 加法版，捕获 (e,f,d) |

数学答案：`d = 2xy + z` → `∂d/∂x = 2y = 6`、`∂d/∂y = 2x = 4`、`∂d/∂z = 1`。

**前半程：建顺序**（`build(d)` 递归）

| 步骤 | 动作 | topo |
|---|---|---|
| ① build(d) | 标记 d，处理 {e,f} → 先 e | [] |
| ② build(e) | 标记 e，处理 {x,y} → x | [] |
| ③ build(x) | 无父节点 → append(x) | [x] |
| ④ build(y) | → append(y) | [x,y] |
| ⑤ 回到 e | 父节点齐 → append(e) | [x,y,e] |
| ⑥ build(f) | e 已访问跳过；append(z) → append(f) | [x,y,e,z,f] |
| ⑦ 回到 d | append(d) | [x,y,e,z,f,d] |

翻转 → `[d, f, z, e, y, x]`

**后半程：逐个调用 `_backward()`**（初始全 0，`d.grad=1`）

| 次 | 调用 | 执行内容 | 此刻 grad (x,y,z,e,f,d) |
|---|---|---|---|
| 1 | `d._backward()` | 加法：`e += 1`、`f += 1` | (0,0,0,**1**,**1**,1) |
| 2 | `f._backward()` | 加法：`e += 1`→**2**、`z += 1` | (0,0,**1**,**2**★,1,1) |
| 3 | `z._backward()` | 空操作 | 不变 |
| 4 | `e._backward()` | 乘法：`x += y×2 = 6`、`y += x×2 = 4` | (**6**,**4**,1,2,1,1) |
| 5 | `y._backward()` | 空操作 | 不变 |
| 6 | `x._backward()` | 空操作 | 不变 |

**最终 `x=6, y=4, z=1`，与 `2y, 2x, 1` 完全一致** ✅

**两个设计回头看**：
- `e` 排第 4 位：因为它在图上被 `d` 和 `f` 共用，必须等两笔账都到
- 叶子有 `lambda: None`：循环无差别调用 `_backward()`，叶子给个空操作就能统一处理，不用写 `if`

## 五、回答"怎么知道上一步是 + 还是 *"

**不需要判断——创建那一刻就已经决定了。**

```python
def __mul__(self, other):
    out = Value(...)
    def _backward():          # 在 __mul__ 里定义
        self.grad  += other.data * out.grad
    out._backward = _backward # 直接钉在 out 身上
```

每个节点出生时，身上被钉好一段专用代码：

| 节点 | 由谁创建 | 身上挂的 |
|---|---|---|
| `e = x*y` | `__mul__` | 乘法版闭包 |
| `f = e+z` | `__add__` | 加法版闭包 |

调用时没有任何 `if`。`_op` 字段**只用于调试显示**，不参与分派。

对比"运行时分支"的写法（本代码**没有**用）：

```python
def _backward(self):
    if self._op == '+': ...
    elif self._op == '*': ...
```

那种写法每加一个运算（`-`、`/`、`tanh`）都要改 `if` 链；而"创建时绑定"只需新增一个 `__sub__` 方法，不动已有代码。
