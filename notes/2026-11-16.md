## 二、细知识点

### 1. 导数的含义

**导数 = 该点的切线斜率 = 函数在这个点"变化得多快"。**

- 导数为正 → 往右走函数值上升
- 导数为负 → 往右走函数值下降
- 导数为 0 → 该点可能是极值点

### 2. 数值求导（中心差商）

```python
def num_diff(f, x, h=1e-4):
    return (f(x + h) - f(x - h)) / (2 * h)
```

- 分子：两点函数值之差（上升量）
- 分母：两点横坐标距离 `2h`（不是 `h`）
- `h` 越小越接近真实导数，但太小会被浮点误差淹没（1e-4 是常用折中）

**验证结果**：`f(x)=x²` 在 `x=3` 得 `6.000000000126`，解析值 `2x=6`，误差 ~1e-11。

### 3. 为什么数值求导重要

深度学习里 `loss.backward()` 算的梯度无法手算验证，而 `num_diff` 只用减法和除法，**永远可信**。

标准做法：**gradient check** —— 用数值梯度校验解析梯度，误差 < 1e-6 视为实现正确。

### 4. 梯度下降（一维）

```python
x = 10.0
lr = 0.1
for i in range(20):
    g = num_diff(f, x)
    x = x - lr * g          # 减号：沿"下坡"方向走
```

- **减号的原因**：梯度指向函数**上升最快**的方向，要下降就得反向
- `lr` 决定每步走多远

### 5. 收敛速度由 `(1 - lr·f'')` 决定

对 `f(x) = x²`（`f' = 2x`）：

```
x_new = x - lr·2x = x(1 - 2·lr)
```

所以每步乘固定倍率 `r = 1 - 2·lr`，第 n 步后 `x_n = x_0 · r^n`。

| lr | r | 行为 |
|---|---|---|
| 0.01 | 0.98 | `0.98²⁰ ≈ 0.667` → `x≈6.68`，极慢 |
| 0.1 | 0.8 | `0.8²⁰ ≈ 0.0115` → `x≈0.115` |
| 0.5 | 0 | 一步到 0 |
| 0.6 | -0.2 | 左右横跳但收敛（`|r|<1`） |
| 1.0 | -1 | 永远在 `±x` 之间弹，不收敛 |
| 1.1 | -1.2 | `|r|>1`，每步放大，发散到 383 |

**结论：收敛条件是 `|1 - lr·f''| < 1`，即 `0 < lr < 2/f''`。** 曲率越大（`f''` 越大），能用的 lr 越小。

### 6. 实测数据（lr=0.1，迭代 20 次）

| 迭代 | x | f(x) |
|---|---|---|
| 17 | 0.1801 | 0.032452 |
| 18 | 0.1441 | 0.020769 |

相邻比值 ≈ 0.8，与公式 `r = 1-2×0.1` 完全一致。

### 7. `round(x, n)`

- `round(3.14159, 2)` → `3.14`，只影响显示，不改变量
- `.5` 时用银行家舍入（`round(2.5)=2`，`round(3.5)=4`）
- 打印更常用 f-string：`f"{x:.4f}"`、`f"{x:.1%}"`

## 三、今天踩的坑 / 值得记的点

1. **以为梯度下降要"加"梯度**：实际是减。因为梯度指向上坡方向。
2. **`num_diff` 的分母写成 `h`**：应该是 `2h`，因为从 `x-h` 到 `x+h` 走了两倍。
3. **`h` 越小越好是错的**：太小会被浮点精度吃掉，1e-4 是常用折中。
4. **lr 不是"越大越快"**：对 `f=x²`，`lr ≥ 1` 直接不收敛；`lr=1.1` 二十步就炸到 383。
5. **"没到 0"不是 bug**：梯度下降是渐近收敛，理论上有无限步才到精确极值。
