## 二、细知识点（本次新增/纠正）

### 1. 张量的三个属性

| 属性 | 例子 | 说什么 |
|---|---|---|
| `shape` | `[2,2]` | 几行几列 |
| `dtype` | `float32` | 数的类型（`1.` vs `1` 决定 float32 / int64） |
| `requires_grad` | `False` | 要不要为它算梯度 |

**整数张量不能求导**：`Only Tensors of floating point and complex dtype can require gradients`。

### 2. 四则运算都是逐元素

`a*b` 是**同格子相乘**，不是矩阵乘；矩阵乘是 `@`。`a+1` 靠广播。

### 3. `@` 的形状规则

$$(n,m)@(m,p)\to(n,p)$$

- 一维 `(3,)` 被当成"一行"
- `(5,3)@(3,2)`：行 = 样本
- 报错读法：`mm: mat1 and mat2 shapes cannot be multiplied (2x3 and 4x2)` → 看 3 ≠ 4

### 4. `requires_grad` 的默认值（不是单一答案）

| 创建方式 | 默认 |
|---|---|
| `torch.tensor([1.,2.])` | **False** |
| `nn.Linear(2,3).weight` | **True** |
| `nn.Parameter(...)` | **True** |
| `with torch.no_grad():` 里创建 | **False** |
| 运算结果（任一输入 True） | **True** |

### 5. `grad_fn` 只在 `requires_grad=True` 的链上出现

```
a 没开 requires_grad → b = a*2 → b.grad_fn = None
a2 开了            → b2 = a2*2 → b2.grad_fn = <MulBackward0>
```

**我一开始让他预测这题，他答"有名字"，错了**——计算图只在"有人要导数"时才建。

`is_leaf` 的判据也不是"源头"：`requires_grad=False` 的张量**一律**是叶子。

### 6. `backward()` 只能对标量

```
RuntimeError: grad can be implicitly created only for scalar outputs
```

所以 `loss` 必须被压成一个数（`.sum()` / `.mean()`）。

### 7. `.grad` 是累加器（今天最费劲的一处）

他连说两次"不懂"，最后退回到"一轮到底是哪 5 步"才通：

```python
pred = w                     # ① 前向
loss = (pred - 0.0) ** 2     # ② 算差距
loss.backward()              # ③ 反向，把导数加进 w.grad
w -= 0.1 * w.grad            # ④ 更新
w.grad.zero_()               # ⑤ 清零
```

| 轮 | 真实梯度 | 有清零用的 | 不清零用的 | 不清零时 $w$ |
|---|---|---|---|---|
| 1 | $4.00$ | $4.00$ | $4.00$ | $1.6$ |
| 2 | $3.20$ | $3.20$ | $7.20=4.00+3.20$ | $0.88$ |
| 3 | $1.76$ | $1.76$ | $8.96=7.20+1.76$ | $-0.016$ |

**第 3 轮就冲过 0。** 一句话：擦了账本，第 ③ 步写进去的才是"这一轮的导数"。

### 8. `nn.Linear` = 两个张量 + 一条公式

```
layer(x)          = [0.7393, -1.0621, 0.0441]
x @ weight.T + b  = [0.7393, -1.0621, 0.0441]
差 = 0.0
```

它替你做了四件事：自动初始化、自动设 `requires_grad`、自动登记到 `parameters()`、自动记计算图。
