## 二、细知识点

### 1. Git 三区四状态

```
工作区(编辑) --add--> 暂存区(index) --commit--> 本地仓库 --push--> 远程
```

| 状态 | 含义 | `git status` 显示 |
|---|---|---|
| untracked | git 从没见过 | 红色 `Untracked files` |
| modified | 跟踪过、被改 | 红色 `Changes not staged` |
| staged | 已进暂存区 | 绿色 `Changes to be committed` |
| committed | 已成快照 | 不显示 |

**关键**：`git commit` 只提交暂存区。直接 commit 会报 `no changes added to commit`。

### 2. Git 命令与参数

| 命令 | 作用 | 要点 |
|---|---|---|
| `git init` | 建 `.git/` | 只在项目根目录跑一次 |
| `git config --global user.name/email` | 设作者 | 写进每个 commit 的 Author |
| `git status [--short]` | 看状态 | `??`=untracked，` M`=modified，`M `=staged |
| `git add 文件` / `.` / `-A` | 进暂存区 | `-A` 会记录删除，最安全 |
| `git commit -m "..."` | 定格快照 | 前缀：feat/fix/chore/docs/refactor |
| `git commit -am` | 自动 add + commit | 只对已跟踪文件有效 |
| `git log --oneline --decorate` | 看历史 | `-3` 限制条数，`--stat` 看文件 |
| `git show HEAD [--stat]` | 看某次提交 | `HEAD~1` 上一次 |
| `git diff` | 工作区 vs 暂存区 | 提交前必看 |
| `git diff --staged` | 暂存区 vs 最新 commit | 即将提交的内容 |
| `git restore 文件` | 丢弃未提交改动 | 不可恢复，慎用 |
| `git restore --staged 文件` | 撤出暂存区 | 改动仍在 |
| `git remote add origin URL` | 加远程别名 | `origin` 是约定名，不是关键字 |
| `git push -u origin main` | 首次推送并绑定 | 之后直接 `git push` |
| `git fetch` + `git log origin/main` | 看远程 | 不动本地文件 |

### 3. `git log` 里的 `(HEAD -> main, origin/main)`

- `HEAD`：指向当前所在的最新 commit
- `main`：本地分支指针
- `origin/main`：远程分支在本地的镜像（上次同步时的位置）
- 三者都指同一行 = **本地与远程同步**；缺 `origin/main` = 本地领先，该 push

### 4. diff 的格式

```
diff --git a/.gitignore b/.gitignore   ← 比较哪两个文件（a/=旧 b/=新）
new file mode 100644                   ← 新建；100644 = 普通文件权限位
index 0000000..7d09be3                ← 内容哈希，全 0 = 旧版本不存在
--- /dev/null                         ← 旧文件为空（Unix 黑洞设备）
+++ b/.gitignore                      ← 新文件有内容
@@ -0,0 +1,3 @@                        ← 块头：@@ -旧起点,旧行数 +新起点,新行数 @@
+.venv/                               ← 新增的行
```

**只看 `+`/`-` 开头的行就是全部改动**，其余是定位脚手架。

### 5. NumPy 掩码

```python
arr  = np.array([[1,2,3],[4,5,6]])   # shape (2,3)，6 个元素
mask = arr > 3                        # [[F,F,F],[T,T,T]]，同形状布尔数组
arr[mask]                             # [4,5,6]，压成一维，shape (3,)
arr[mask].mean()                      # (4+5+6)/3 = 5.0  ← 分母是 3，不是 6
arr[mask].size                        # 3
```

- 掩码索引 = **抽取**，不是筛选后保留形状
- `(cond).sum()` = 满足条件的**个数**
- `(cond).mean()` = 满足条件的**比例**（与图像尺寸无关，更适合做指标）

### 6. 图像与通道

- `img.shape = (行, 列, 通道)`，彩色图 = 3 个二维矩阵叠起来（B/G/R）
- OpenCV 的**坐标**是 `(x, y)` = `(列, 行)`，与 numpy 索引 `img[行, 列]` **相反**
- BGR 顺序：红 = `(0,0,255)`，白 = `(255,255,255)`，黑 = `(0,0,0)`
- 灰度转换是加权合并：`Gray = 0.299R + 0.587G + 0.114B`（绿色权重最大）
- 图像必须 `dtype=np.uint8`（0–255，1 字节）；默认 `float64` 会内存 ×8 且被 cv2 拒绝

### 7. `cv2.rectangle` 签名

```python
cv2.rectangle(img, (x1,y1), (x2,y2), color, thickness)
```
- `thickness = -1` 实心，正数为边框宽度
- 坐标含两端：`(10,10)-(40,40)` 的宽高都是 `40-10+1 = 31`，面积 `31² = 961`

### 8. 阈值扫描 = 累积直方图的离散采样

```python
for t in range(0, 256, 32):
    count = (gray > t).sum()
    ratio = count / gray.size
```

本次结果：

| t | count | ratio | 变化 |
|---|---|---|---|
| 0–96 | 2883 | 0.144 | 三块都在（3×961） |
| 128 | 1922 | 0.096 | 暗块（100）掉队 |
| 160 | 961 | 0.048 | 中块（150）掉队 |
| 192 | 961 | 0.048 | 只剩亮块（200） |
| 224 | 0 | 0.000 | 全灭 |

- 每级台阶 = 一块的面积
- 台阶位置 = 该块的灰度值 + 1（`gray > t` 是严格大于）
- 真实图像灰度连续 → 阶梯变平滑曲线，但"越暗越先消失"不变

### 9. Otsu 大津法

```python
t, binary = cv2.threshold(gray, 0, 255, cv2.THRESH_BINARY + cv2.THRESH_OTSU)
```
- 原理：遍历所有阈值，选**类间方差最大**的那个，即让前景/背景分得最开
- **前提假设**：直方图双峰、前景背景比例别太悬殊、前景内部亮度单一
- 本次得到 `0.0`：黑底 85.6% 压倒性地拉偏分割线；且三块亮度不同，Otsu 只会切两类
- 失效的替代方案：
  - `cv2.adaptiveThreshold`（局部窗口自算阈值，抗光照不均）
  - 分块 Otsu
  - 用梯度/边缘（Canny）而非亮度
  - 神经网络（学出来的特征，不依赖手工阈值）

## 三、今天踩的坑

1. **`git commit` 前忘了 `git add`** → `no changes added to commit`。三区模型没建立起来。
2. **`git show` 进了 pager 出不来** → 按 `q`；或 `--no-pager`。
3. **`git restore` 覆盖了磁盘上的 scratch.py** → VS Code 报"无法保存"，因为编辑器里有未保存改动。外部改文件后必须先处理冲突。
4. **改了代码没 `Ctrl+S` 就运行** → 跑的是磁盘旧版本，得到 `(50, 80, 0)` 这种莫名结果。
5. **`np.zeros((50,80,3), 255, ...)`** → `zeros` 没有填充值参数，255 被当成 dtype。换函数必须换参数。
6. **白底导致"红像素=全图"** → `(red>0)` 把白色背景也算进去（白 = 255,255,255）。通道值大 ≠ 是红色，判断颜色要三通道一起看。
7. **`arr[mask].mean()` 预测错** → 以为是全数组平均，实际分母是选中个数。
