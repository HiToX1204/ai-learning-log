## 二、细知识点

### 1. `np.arange` 语法

```python
np.arange(stop)                # 从 0 开始，步长 1
np.arange(start, stop)         # 指定起点
np.arange(start, stop, step)   # 指定步长
```

- **左闭右开**：不含 `stop`
- 返回 **ndarray**（`range` 返回惰性对象，不能 reshape）
- 浮点步长可能因精度多/少一个，**要精确个数用 `np.linspace`**

### 2. `reshape` 语法

```python
a.reshape(3, 4)      # 直接给整数
a.reshape((3, 4))    # 给元组（等价）
a.reshape(3, -1)     # -1 自动补，且只能出现一次
a.reshape(-1)        # 展平成一维
```

- 元素总数必须一致，否则 `ValueError`
- 默认 **C order（行优先）**：最后一维变化最快

### 3. 行优先填充的扁平索引公式

对 `shape = (2,3,4)`，下标 `[i,j,k]` 的扁平位置：

```
flat = i×12 + j×4 + k
```

对照表：

| 下标 | 计算 | 值 |
|---|---|---|
| `[0,0,0]` | 0 | 0 |
| `[0,1,0]` | 4 | 4 |
| `[0,2,1]` | 8+1 | 9 |
| `[1,0,0]` | 12 | 12 |

### 4. 视图（view）与复制（copy）

| 操作 | 是否共享内存 |
|---|---|
| `reshape`（内存连续时） | 共享（视图） |
| `transpose` | 共享（视图） |
| `.T` | 共享（视图） |
| `astype` | 复制 |
| `reshape`（内存不连续时） | 复制 |

检查手段：

```python
np.shares_memory(a, b)      # True / False
```

**后果**：改视图会改原数组。`b[0,0]=99` 后 `a[0]` 也是 99。

### 5. `transpose` 的轴映射

```python
y = x.transpose(2, 0, 1)     # 新数组第0轴←原第2轴，第1轴←原第0轴，第2轴←原第1轴
x.shape (2, 3, 4) → y.shape (4, 2, 3)
```

**索引关系：`y[a, b, c] == x[b, c, a]`**

常用场景：

```python
img.transpose(2, 0, 1)              # (H,W,C) → (C,H,W)      给 PyTorch
batch.transpose(0, 3, 1, 2)         # (B,H,W,C) → (B,C,H,W)
```

注意：高维 `.T` 会把所有轴**完全反转**（`(2,3,4)→(4,3,2)`），一般不是想要的结果，**要用显式 `transpose`**。

### 6. 为什么转置是零成本（strides）

NumPy 在内存里只存"一排数"+ 一组步长：

- `x` 步长 `(12,4,1)` → `[i,j,k]` 位置 = `12i+4j+k`
- `y = x.transpose(2,0,1)` 步长变成 `(1,12,4)` → `[a,b,c]` 位置 = `a+12b+4c`

内存里的数一个没动，**只换了步长表**，所以转置不复制。

### 7. 向量化：为什么快 86 倍

| 写法 | 耗时（100 万个数求和） |
|---|---|
| Python `for` 循环 | 0.0516 s |
| `r.sum()` | 0.0006 s |

- `for` 循环：每个元素都过一遍解释器（类型检查、方法查找、加法分派）
- `r.sum()`：编译好的 C 循环，可 SIMD 并行

**结果末位不同**（`...2353` vs `...2415`）是因为浮点加法**不满足结合律**，求和顺序不同误差不同。

### 8. `np.random.randint`

```python
np.random.randint(low, high, size, dtype=...)
#                  含    不含   形状
```

- `np.random.randint(0, 256, (100,200), dtype=np.uint8)` → 100×200 的 0–255 随机整数

### 9. 聚合函数一览（对 `(100,200)` 的 `g`）

| 写法 | 返回 | 形状 |
|---|---|---|
| `g.sum()` | 总和 | 标量 |
| `g.sum(axis=0)` | 每列和（压掉行） | `(200,)` |
| `g.sum(axis=1)` | 每行和（压掉列） | `(100,)` |
| `g.mean()` / `axis=0/1` | 平均 | 同上规律 |
| `g.argmax()` | **扁平索引** | 标量 |
| `g.argmax(axis=0)` | 每列最大值所在行号 | `(200,)` |

**规则：`axis=k` 压掉第 k 维，结果长度由剩下的维度决定。**

### 10. 布尔掩码的两种聚合

```python
(img > 128).sum()      # 个数（int64）
(img > 128).mean()     # 比例（float64）= sum / size
```

`mean` 永远返回浮点，因为它是除法。

### 11. `argmax` 的三种形态（对 `a = np.arange(20).reshape(4,5)`）

| 写法 | 结果 | 含义 |
|---|---|---|
| `a.argmax()` | `19` | 扁平位置 |
| `a.argmax(axis=0)` | `[3 3 3 3 3]` | 每列最大值所在行 |
| `a.argmax(axis=1)` | `[4 4 4 4]` | 每行最大值所在列 |

扁平索引 ↔ 坐标：`flat = i*5 + j`；反向 `i = flat//5`，`j = flat%5`。
换回坐标用 `np.unravel_index(a.argmax(), a.shape)` → `(3, 4)`

## 三、今天踩的坑

1. **`reshape` 一开始被理解成"改变数据"**：实际只是换分组方式，数字顺序完全不变。
2. **轴映射方向搞反**：曾以为 `y[1,2,3]` 对应 `x[3,1,2]`。两个问题：方向反了、且两边都越界。**越界是推导错误最快的报警器。**
3. **把第三个 print 的输出误认为第一个**：看到 38–65 以为均值不对，实际那是 `(img>128).sum(axis=0)` 的每列计数。**看输出要先确认是哪个 print 的。**
4. **对象选错 + 聚合选错**：`(col_mean > 128).sum()` 算的是"多少列均值大于 128"（93 列），而题目要"多少像素大于 128"（比例 0.496）。代码能跑、数字也合理，但**回答的不是那个问题**。
5. **以为 `argmax` 返回坐标**：不写 `axis` 时返回的是扁平索引。
6. **`(a>10).mean()` 带小数点不是错误**：除法必然返回浮点。
