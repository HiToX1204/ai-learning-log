## 关键结论（按模块归集）

### 环境与工具链
- PATH 从左到右找命令，**第一个命中即停**；`WindowsApps` 里的是 0 字节"应用执行别名"，指向未安装的应用，所以敲 `python` 会报"找不到路径"
- 环境变量是**进程启动时的快照**，改注册表不影响已开的窗口
- 用 `uv run python xxx.py` 代替激活脚本，绕开执行策略问题

### 数组基础
- 一张图 = `(行, 列, 通道)` 的三维数组；通道是"同一个点上的多个数值"，不是"深度"
- `axis=k` 压掉第 k 维，结果长度由剩下的维度决定：`axis=0` 压行（结果 = 列数）
- `reshape` 不改数据，只改"怎么分组"；默认按行优先（最后一维变化最快）
- 布尔掩码 `arr[mask]` 是**抽取**，会把结果压成一维；`.mean()` 的分母是选中个数
- `mean` 永远返回浮点（除法），`sum` 保持整数
- `argmax()` 不写 axis 时返回**扁平索引**，不是行列坐标；平局取第一个

### 数组进阶（视图·广播·向量化）
- `reshape` / `transpose` 通常是**视图**（共享内存），`astype` 是复制；用 `np.shares_memory` 验证
- 改视图会改原数组：`b[0,0]=99` 后 `a[0]` 也是 99
- `transpose(2,0,1)` 的索引关系：**`y[a,b,c] == x[b,c,a]`**；`(H,W,C)↔(C,H,W)` 可用往返 `array_equal` 自检
- 转置零成本的原因：内存不变，只换步长表（strides）
- 广播：从右往左对齐，某维相等或为 1 即可；`[None,:,None]` 用来插入长度 1 的轴
- 向量化比 Python 循环快约 **86 倍**（100 万个数求和：0.0516s vs 0.0006s）

### 版本管理
- 三区模型：工作区 →（add）暂存区 →（commit）本地仓库 →（push）远程
- `commit` 只认暂存区，不 `add` 会报 `no changes added to commit`
- `commit` 只存在本地；`push` 才上 GitHub

### 表格数据（pandas）
- `DataFrame` 是带列名的二维表；`df["列"]` 得到一维 `Series`，`df[["列"]]` 仍是表
- 按条件筛行：`df[df["detected"]]`，多条件用 `&` 且每项加括号
- `groupby(键)["列"].mean()` 是分组统计；**布尔列求平均 = 比例**（检出率）
- `idxmin()` 返回最小值的**标签**（组名），`argmin()` 返回位置
- `to_csv(index=False)`：不把行号写成列，否则读回会多一列 `Unnamed: 0`
- `NaN`：不等于自己（要用 `isna` 判断）；整数列含 NaN 会升级为 `float64`；pandas 的 `sum/mean` 默认跳过 NaN，NumPy 不会
- 版本差异：pandas 3.x 字符串列是 `str`（旧版是 `object`），且 `read_csv` 能自动识别 `True/False` 为 `bool`

### 数学直觉（导数与梯度）
- 导数 = 该点的切线斜率 = "变化得多快"；正 → 往右上升，负 → 往右下降，0 → 可能是极值
- 数值求导用中心差商 `(f(x+h) - f(x-h)) / (2h)`（分母是 `2h`）；`h` 太小会被浮点误差淹没，1e-4 是常用折中
- 它是**唯一可信的校验手段**：gradient check 用数值梯度校验解析梯度，误差 < 1e-6 才算实现对
- 梯度下降三行：`g = 导数`；`x = x - lr*g`（**减号**：梯度指向上坡，要反向走）
- 对 `f=x²`，每步乘 `r = 1 - 2·lr`，收敛条件是 `|1 - lr·f''| < 1`（即 `0 < lr < 2/f''`）
- 实测：`lr=0.01` 太慢（20 步后 x≈6.68）、`lr=0.5` 一步到 0、`lr=1.1` 发散（x≈383）
- 曲率越大，能用的 lr 越小；"没收敛到精确 0"是渐近收敛的正常现象

### 图像应用（判据与检测）
- 阈值扫描是阶梯函数：每级台阶 = 一块目标的面积
- 阈值是绝对的、光照是相对的；光照整体变暗会让固定阈值整块失效（本例 1922 → 0）
- Otsu 只适合"双峰、前景背景比例接近"的图；黑底占 85% 时它会选 0
- 换用梯度判据（Canny）能在同一光照变化下稳定检出（360 → 360），但只给轮廓，仍需 findContours + 几何条件筛选

### 自动微分（micrograd）
- `Value` 类的意义不是"算出 4.0"，而是**记住 4.0 是怎么算出来的**（`data` + `_prev` + `_op` 构成计算图）
- `__add__` / `__mul__` 是运算符重载：让 `a*b` 自动建图，而不是直接算出 float
- 每个节点只需知道**自己的局部导数**，全局梯度靠链式法则逐级相乘传递
- `_backward` 的通用式：**`我的梯度 += 局部导数 × out.grad`**；加法局部导数是 1，乘法是对方的值
- **必须用 `+=`**：多路径时梯度要相加（全导数 = 各路径偏和）；用 `=` 会覆盖 → PyTorch 的 `zero_grad()` 就是防这个
- **`out.grad` 不能写死 1.0**：图越深，上游传来的梯度越不是 1
- 反向传播顺序 = **后序拓扑 + 翻转**（`append` 在递归之后，再 `reversed`）；翻两次等于没翻
- 顺序错了**不报错**：`e` 提前结算时 `grad=0`，导致上游梯度全为 0

### 线性代数（数学补丁 M1）
- 矩阵乘向量两种读法，结果相同：**行视角**=每行点乘出一个数（代码里 `@` 干的）；**列视角**=把两列按坐标比例叠加（图形怎么动的解释）
- 恒等式：$A(1,0)$ = 第 1 列，$A(0,1)$ = 第 2 列 —— "两列 = 坐标轴去向"是代入算出的，不是观察规律
- **形状账只有一条**：`(n,m) @ (m,p) → (n,p)`，中间必须相等。转置的唯一作用是把 $(4,2)$ 翻成 $(2,4)$ 好让中间对上
- **`W` 的行 = 神经元，`x` 的行 = 样本**；两个"行"不是一回事。结果 $(n,k)$ 读作"$n$ 个样本被 $k$ 个神经元各读一次"
- `nn.Linear(2,4)` 的 `(4,2)` 直译 = 4 个神经元各看 2 个输入；偏置 `b` 的形状是 $(4,)$，每个神经元一个
- 权重最朴素的锚点是加权平均（总评 $=0.3$ 平时 $+0.7$ 期末）；但不能当"占比"——可以为负、不必和为 1，准确说法是**影响系数**
- 两层线性合并：$W_{\text{合并}}=BA$（**后做的在左**）；直观读法是**路径求和**（枚举中间所有路径，各段相乘再相加）
- 纯线性叠加会塌缩：中间层宽度在合并结果里**不可见**（$(2,5)$+$(3,2)\to(3,5)$），所以"加深"必须靠非线性
- 维度三种方向都合法：放大（$2\to4$）、等维（$4\to4$ 换指标）、压缩（$4\to1$，**有损**）；输出比输入少是因为"最终只要一个答案"
- 对拍是自保手段：慢而显然正确的实现 vs 一行快实现，比差值（本例手写三重循环 vs `X@W.T+b`，$diff=0.0$）
- `xor_mlp.py` 里 $W_1$ 存 $(2,4)$（输入数在前）用 `X@W1`；`nn.Linear` 存 $(4,2)$（神经元数在前）用 `X@W.T` —— 同一层两个存放方向，形状数字会骗人

### 线性代数（数学补丁 M2）
- 特征向量 = 乘完**方向不变**、只变长短的方向；判据 $Av=kv$（两个分量同比例）。别的方向都会被拐弯
- 求法：$(A-\lambda I)v=0$ 有非零解 ⇒ 两行成比例 ⇒ det$(A-\lambda I)=0$；$2\times2$ 用"左上×右下 − 右上×左下"
- 自检：两 $\lambda$ 之和 = 主对角线之和（$3+1=4=2+2$）
- 梯度下降在特征方向上是 $(1-\eta\lambda)$ 倍：**各方向独立缩放**，互不干扰，且是精确成立（闭式与循环对拍 $diff=0$）
- 收敛条件 $|1-\eta\lambda|<1$ 对所有方向成立 ⇒ $\eta<2/\lambda_{\max}$；一维退化为 $0<\eta<2/f''$
- 危险方向 = $\lambda$ 最大的那个；$\eta$ 恰好等于 $2/\lambda_{\max}$ 时 $r=-1$，长度不变、符号来回翻（临界不收敛）
- **学习率 = 步幅**（你自己定的唯一旋钮）；梯度 = 坡度（地形给的）。$f=x^2$ 在 $x=3$：$\eta=0.1\to2.4$、$0.5\to0$、$1.1\to-3.6$
- $\lambda$ 的抽象理解：**地形的陡**。主要由**输入尺度**决定，输出 $y$ 只决定碗底在哪；归一化 = 把地形压缓 = 允许更大 lr
- 三档实测（$f=\frac12x^\top Ax$，起点长度 $\sqrt2$）：$\eta=0.5\to0.0221$、$2/3\to1.4142$、$0.7\to2.5054$

### 训练闭环与分类（W3）
- `nn.Linear(in, out)` 的 `weight` 是 `(out, in)`（**神经元数在前**），`bias` 是 `(out,)`，参数数 `out*in+out`
- 训练循环 5 行顺序固定；`zero_grad` 必须在 `backward` 之前，否则 `step` 读到 0（实测参数永远不动）；写在循环末尾等价
- **MSE = Mean Squared Error**：$(\text{pred}-Y)^2$ 的均值。预测全 0.5、答案 0/1 时 $=0.25$
- **MSE 与准确率会打架**：同一批点上，常数 0.5 的 MSE $=0.25$/acc $0.500$；$2x_1+2x_2-3$ 的 MSE $=18.5$/acc $0.625$——准确率高的解被 MSE 罚 74 倍
- 内圆 + 外环数据：线性模型 acc $0.555$（$w\approx0$、$b=0.5$，塌成常数）；MLP $2\to16\to\text{ReLU}\to1$ 达 $1.000$，参数 $3\to65$
- 线性模型失败的几何原因：等值线是**平行直线**，理想答案是**同心圆**；同一类点分数跨度可达 $11.25$（$-8.63\sim2.62$），而正确答案要求全部 $>0.5$
